# Практична робота №5. AJAX і JSON: онлайн-анкета

Варіант 12: **Онлайн-опитування/анкети**.

Сторінка завантажує список питань через `fetch`, фільтрує його «наживо» за типом питання, відправляє відповіді на сервер без перезавантаження та оновлює індикатор прогресу проходження анкети.

## 🚀 Запуск

### Вимоги
- PHP 8.x з розширенням `pdo_sqlite`
  - Linux/macOS: `php -m | grep pdo_sqlite`
  - Windows: `php -m | findstr pdo_sqlite`
- Окремий сервер бази даних **не потрібен**: використовується SQLite

### Кроки
1. Перейдіть у директорію проєкту:
```bash
cd lab5
```
2. Запустіть вебсервер:
```bash
php -S localhost:8000
```
3. Відкрийте `http://localhost:8000/index.html`.

Файл бази `survey.db`, обидві таблиці та 8 тестових питань створюються автоматично при першому запиті (див. `db.php`). Щоб скинути всі відповіді, зупиніть сервер і видаліть `survey.db`.

<details>
<summary>Якщо розширення pdo_sqlite не увімкнено</summary>

- **Windows / XAMPP:** відкрийте `php.ini` (у XAMPP: `C:\xampp\php\php.ini`), знайдіть рядки `;extension=pdo_sqlite` та `;extension=sqlite3`, приберіть `;` на початку, перезапустіть вебсервер.
- **Ubuntu/Debian:** `sudo apt install php-sqlite3`
- **macOS (Homebrew):** розширення входить до складу `php`, додаткових кроків не потрібно.
</details>

<details>
<summary>Запуск через XAMPP / Apache</summary>

Скопіюйте папку проєкту в `htdocs` (у XAMPP: `C:\xampp\htdocs\lab5`), запустіть Apache і відкрийте `http://localhost/lab5/index.html`. Папка проєкту має бути доступна PHP для запису: у ній створюється файл `survey.db`.
</details>

## 📁 Структура проєкту

| Файл | Призначення |
|------|-------------|
| `index.html` | Сторінка: поле пошуку, індикатор прогресу, порожній контейнер `#results` |
| `script.js` | Уся клієнтська логіка: `fetch`, пошук, відправка відповідей, оновлення DOM |
| `api_list.php` | JSON-ендпоінт списку питань (із фільтром `?q=`) |
| `api_add.php` | JSON-ендпоінт збереження відповіді (POST) |
| `db.php` | Підключення до SQLite, створення таблиць і тестових даних |
| `schema.sql` | Схема таблиць у вигляді SQL (довідково / для варіанта з MySQL) |

## 🗄️ База даних

- `questions (id, text, type)`: питання; `type` ∈ `text`, `rating`, `yesno`
- `answers (id, question_id, answer_text, created_at)`: відповіді, `question_id` посилається на `questions.id`

## 🔌 API

### `GET api_list.php?q=<рядок>`
Повертає JSON-масив питань. Параметр `q` фільтрує за типом (`LIKE`), без `q` повертаються всі питання.

```json
[
  { "id": 3, "text": "Оцініть зручність курсу (1-5)", "type": "rating", "answered": false }
]
```

### `POST api_add.php`
Тіло запиту (JSON): `{ "question_id": 3, "answer_text": "5" }`

| Код | Значення |
|-----|----------|
| `201` | Відповідь збережено; у тілі є `answered` і `total` для індикатора прогресу |
| `400` | Не передано `question_id` або відповідь порожня/задовга |
| `404` | Питання не знайдено |
| `405` | Метод не POST |
| `409` | На це питання вже є відповідь |
| `500` | Помилка бази даних |

Усі помилки повертаються у форматі `{ "error": "..." }`.

## ✅ Що реалізовано

- Список питань завантажується через AJAX, без PHP-виводу таблиці в `index.html`
- Живий пошук за типом питання (подія `input`, затримка 250 мс, захист від «застарілих» відповідей)
- Відправка відповіді через `fetch` + `event.preventDefault()`, без перезавантаження сторінки
- Індикатор прогресу «N з M» оновлюється одразу після відповіді; рахується по всіх питаннях, а не по відфільтрованих
- Обробка помилок (`response.ok`, `.catch`): повідомлення показується на сторінці, а не лише в консолі
- Захист від XSS: тексти вставляються через `textContent`, а не `innerHTML`
- SQL-запити лише через підготовлені вирази (prepared statements)

## 🔍 Перевірка в DevTools

1. Відкрийте вкладку **Network**, увімкніть фільтр **Fetch/XHR**.
2. Оновіть сторінку: з'явиться запит `api_list.php`.
3. Введіть у пошук `rating`: з'являються нові запити `api_list.php?q=rating`.
4. Надішліть відповідь: з'являється `api_add.php` (POST, статус `201`).
5. На вкладці **Elements** видно, що DOM змінюється, а документ не перезавантажується.
